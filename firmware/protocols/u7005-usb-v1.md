# U7005: установочный USB-образ, версия 1

Формат собственного комплекта поверх штатного LDROM 15. Поведение MSI-загрузчика
и источники адресов описаны в [u7005-ldrom.md](../../docs/u7005-ldrom.md).
Этот документ задаёт новые артефакты и контракт приложения с упаковщиком.

## Дескриптор приложения

После 48 векторов Cortex-M0, по адресу `000000C0`, находятся 16 байт:

| Смещение от C0 | Размер | Значение |
|---|---|---|
| 0 | 4 | ASCII `U7BI` |
| 4 | 4 | uint32 LE, версия 1 |
| 8 | 4 | uint32 LE, длина кода с начальными данными и RAM-кодом FMC |
| 12 | 4 | uint32 LE, flags=1: нормализация метаданных перед USB |

Длина равна linker symbol `_code_end`, кратна 4, не больше `10000`.
Упаковщик сверяет её с BIN и отвергает неизвестные flags/версии и старые сборки
без дескриптора. Маркер объявляет контракт, но не является цифровой подписью.
Действительная реализация подтверждается проверками исходного C и итогового ELF.

## Установочный комплект

`NAME.bin` содержит ровно `1F7F8` байт с адреса 0, без заголовка:

| Диапазон | Данные |
|---|---|
| `[0,code_length)` | Собственное приложение |
| `[code_length,10000)` | FF |
| `[10000,15800)` | Новый FAT12-диск, 44 сектора |
| `[15800,1F7F8)` | Байты резервного APROM, включая страницу USB mode |

Старый код в первых 64 КиБ целиком заменяется. DataFlash `[1F800,20000)` не
передаётся. Метаданные по `1F7F8/1F7FC` загрузчик создаёт сам после передачи.
Парный `NAME.json` с `format=u7005-usb-v1` содержит длину, SHA-256 и sum16 всего
BIN, отдельные данные кода, хеш диска и сохранённого хвоста, USB mode, PDID,
LDROM version/checksum, CONFIG0/1/2 и хеши резервных APROM/CONFIG/DataFlash с board ID.
Перед открытием USB утилита проверяет все части комплекта.

Цель v1 фиксирована: PDID `01205206`, LDROM `15/D926`,
CONFIG `FFFFFB7E/0001F800/FFFFFF5A`. LDROM по USB сообщает только CONFIG0/1;
CONFIG2 проверяется в файле при подготовке и не переписывается.
Исходный APROM должен быть полным 128-КиБ дампом с согласованной загрузочной суммой.
Отсутствие цифровой подписи означает, что хеши защищают от несогласованности файлов,
а не от умышленной замены комплекта.

## Первый запуск

До `bridge_init` и включения USB приложение читает метаданные через FMC.
Допустимы только длина собственного кода или `1F7F8`. Сумма должна быть uint16,
сохранённым в uint32 LE; все FMC READ обязаны завершиться успешно.

Если метаданные уже описывают код и его сумма совпадает, записи нет. Если они
описывают полный USB-образ, приложение проверяет его сумму и вычисляет сумму
префикса кода. Затем сохраняет страницу `1F000…1F7FF` в SRAM, заменяет последние
8 байт длиной/суммой кода, стирает страницу и записывает её словами по возрастанию
адреса. Таким образом, длина и сумма пишутся последними. Страница проверяется
побайтово через сравнение всех прочитанных слов; метаданные дополнительно читает
проверка загрузочной политики. Остальные страницы при этом не записываются.

При несовпадении суммы, неверной длине или ошибке FMC приложение уходит в LDROM
через BS=1 и CPU reset, не открывая прикладной USB. После успешной нормализации
диск и USB mode находятся вне загрузочной суммы. B0 возвращает сумму только кода.

Операция страницы не атомарна. В модели обрыва между завершёнными FMC-операциями
до последнего слова поле суммы остаётся `FFFFFFFF` и отвергается LDROM.
Поведение при физическом обрыве erase/program не проверялось и этой моделью
не гарантируется. При зависшем FMC RAM-примитив остаётся в SRAM.

## Хост записи

Хост посылает только A0/00 для записи APROM, сверяет ACK sum16/sequence и итоговую
sum16. При потере ответа он не знает, закончилась ли запись блока, и прекращает
сеанс. Повторы FF, CONFIG A1, полное стирание A3 и DataFlash C3 не используются.
AF запускает приложение после проверки загрузчиком длины/суммы; AB не используется.
`--stay-in-isp` откладывает AF для независимого чтения через SWD.

Успешный результат означает, что передача проверена суммами, приложение отвечает
по USB, а U7EX, B0, board ID и mode совпали с ожидаемыми. Это не проверка всех
команд моста или побайтовое независимое чтение записанного APROM. Каталог сеанса
содержит точный BIN, исходные отчёты USB, параметры комплекта и этап завершения.
