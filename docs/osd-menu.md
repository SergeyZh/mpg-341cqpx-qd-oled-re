# Пользовательское меню (OSD) и экран Panel Protect

Разобрано по фото обычного меню (`monitor_menu.jpeg`, FW.034) и сопоставлено с образом.

## Да, меню целиком лежит в прошивке

Все пункты с фото найдены: `G.I.`, `Gaming`, `Professional`, `Image`, `Input Source`,
`PIP/PBP`, `Navi Key`, подменю `KVM` / `Smart Crosshair` / `Optix Scope`, значения
`Auto` / `Upstream` / `Type C`, а также элементы шапки — `Pro Mode`, `Adaptive-Sync`, `HDR`.

Заголовок окна — `MPG 341C QD-OLED` (файл 0x259919). Обратите внимание: это **не то же
самое**, что имя в EDID (`MPG341CX OLED`) и не то, что в сервисном меню. Три разных
строки для трёх разных мест.

Форматы шапки: `n%4dX%4d` (разрешение), `n%d HZ` (частота), `n %d, %dh  %dm` (время).

### Устройство таблицы строк

Строки OSD хранятся **с байтом длины в начале** (как и в сервисном меню), сгруппированы
по пунктам: на каждый пункт идёт 18–20 языковых вариантов подряд. Пример для `Navi Key`
(файл 0x258C48–0x258C80): `Tasto Navi`, `Navigationssteuerung`, `Touche Navi`, `Navi Key`.

Главное меню занимает 0x258C00–0x2599A0, подменю и значения — 0x240000–0x258000.

**Код обращается к строкам по индексам, а не по адресам.** Поиск ссылок `sethi`/`or`
на эти строки не даёт ничего — в отличие от отладочных строк, где он работал. Поэтому
привязать пункт меню к переменной автоматически пока нельзя; нужен разбор таблицы
индексов OSD.

## Экран Panel Protect — самое ценное

По соседству с обычными пунктами обнаружился набор строк, у которых **нет переводов**
и которые оформлены как подписи со знаком двоеточия. Это признак заводского или
диагностического экрана, а не пользовательского меню.

Файл 0x24BE00–0x24BE9C (Main адреса 0x143E00–0x143E9C):

```
0x143E00  'HDR'
0x143E08  'HDR ON'
0x143E10  'Bri. Reduce Timing:'        <- через сколько снижать яркость
0x143E28  'Bri. Reduce Ratio:'         <- насколько снижать
0x143E40  'Static Screen Detection:'
0x143E60  'Pixel Shift:'
0x143E70  'Long Time:'
0x143E80  'Short Time:'
0x143E90  'Panel Protect'
```

Рядом лежат наборы допустимых значений:

| Набор | Значения | Вероятное назначение |
|---|---|---|
| 0x143EB8 | `100% 80% 60% 40% 20%` | грубая шкала, 5 шагов |
| 0x143F00 | `95% 90% 85% 80% 75% 70% 65%` | **Bri. Reduce Ratio**, 7 шагов |
| языковые | `50 Sec`, `100 Sec`, `120 Sec`, `240 Sec` | **Bri. Reduce Timing** |

То есть снижение яркости статичной картинки параметризовано двумя величинами:
задержкой в секундах и глубиной снижения в процентах, вплоть до 65 % от исходной.
Это ровно тот механизм, который в терминологии из `docs/external-research.md`
называется ASBL — и он, в отличие от ABL, настраивается.

**Все эти строки присутствуют и в FW.034**, то есть экран доступен на текущей прошивке
монитора (в 034 они лежат на 0x24BA89 и далее).

## Экран MSI OLED Care → OLED Panel Info (снят с монитора)

Фото `panel_protect_menu.jpeg`, FW.034. Показывает:

| Пункт | Значение |
|---|---|
| Panel Protect | `155, 0h 36m` |
| Pixel Shift | `Normal` |
| Static Screen Detection | ON |
| Multi Logo Detection | ON |
| Taskbar Detection | ON |
| Boundary Detection | ON |

### Взаимное подтверждение прошивки и железа

Каждый пункт этого экрана ложится ровно на регистр панели, расшифрованный ранее
из кода (`docs/oled-panel-abl.md`) — независимо и до того, как экран был увиден:

| Пункт OSD | Регистр панели | Функция в Main |
|---|---|---|
| Static Screen Detection | **0x060** Screen Saver Range | 0x000C30CC |
| Multi Logo Detection | **0x1B2** MultiLogo | 0x000C35B4 |
| Taskbar Detection | **0x1B6** Task Bar | 0x000C3440 |
| Boundary Detection | **0x1B4** Pillar Box | 0x000C32CC |
| Pixel Shift = `Normal` | **0x070** вкл/выкл + **0x072** скорость | 0x000C2DE4 / 0x000C2F58 |
| Panel Protect (счётчик) | **0x0C0** OFF Sensing / **0x0C2** EL Sensing | 0x000C2BCC / 0x000C2C38 |

Это сильное подтверждение: расшифровка I2C-протокола, сделанная только по
дизассемблеру, полностью совпала с тем, что монитор показывает пользователю.
«Boundary Detection» в интерфейсе — это `Pillar Box` в протоколе, то есть
защита границ картинки при неполном заполнении экрана.

### Счётчик Panel Protect

`155, 0h 36m` печатается форматом `n %d, %dh  %dm` (Main адрес 0x1518B0).
Первое число — **количество выполненных циклов компенсации** панели, дальше время.

Сходится с данными сервисного меню: наработка там 843 часа, то есть примерно
**один цикл на 5,4 часа работы**. Для OLED это нормальный интервал короткой
компенсации. Сами циклы — это и есть OFF Sensing и EL Sensing.

Счётчик уникален для экземпляра и хранится в FE2P (`docs/fe2p.md`); при поиске
FE2P в дампе значение 155 — дополнительный ориентир помимо серийного номера.

## Что это меняет для проекта

До сих пор параметры ограничения яркости были известны только как имена переменных
в образе Tensilica (`ADIM`, `LimitUpperBound`, `ZonePeakingPercent` — см.
`docs/oled-panel-abl.md`), без доступа к ним. Теперь видно, что у части этого контура
есть **человекочитаемый интерфейс с дискретным набором значений**.

Экран `OLED Panel Info` даёт **чтение** состояния защиты панели, но не настройку
глубины снижения яркости: `Bri. Reduce Timing` и `Bri. Reduce Ratio` на нём
отсутствуют.

**Поправка к предыдущей гипотезе.** Раньше я предполагал, что строки `Bri. Reduce *`
могут оказаться доступным в заводском режиме экраном настройки. Снятое фото это
не подтверждает: в `MSI OLED Care` их нет. Они лежат в отдельном блоке
(0x143E00–0x143E9C) со своими списками значений и относятся к какому-то другому
экрану — либо к недоступному через OSD, либо к неиспользуемому остатку.
Пока не найден код, который их выводит, считать их настраиваемыми нельзя.

Что при этом установлено твёрдо: четыре механизма детекции статики и Pixel Shift
**включены и управляются штатно**, а соответствие «пункт меню → регистр панели»
теперь известно полностью. Это и есть работающий путь к настройке защиты панели —
через I2C-команды, а не через поиск скрытого экрана.

## Чего пока нет

> **Обновление 2026-09-27 (FW.034):** таблица индексов строк разобрана, пункты меню
> доведены до действий — osd-menu-functions.md (не опубликовано). Экрана с
> подписями `Bri. Reduce …` в FW.034 нет: на строки нет ни одной ссылки
> (§6.5 (не опубликовано)); его аналог —
> подпункты Static Screen Detection. Текст ниже — исходное состояние.

Не найден код, который рисует этот экран и хранит текущие значения. Причина
техническая: OSD адресует строки по индексам таблицы, а не указателями, поэтому
приём с поиском `sethi`/`or`-ссылок, сработавший для отладочных строк, здесь
не применим. Соответствие «пункт меню → переменная в DRAM» требует разбора
таблицы индексов OSD и пока не установлено.

Поэтому наборы значений выше сопоставлены пунктам **по расположению и логике,
а не по коду**. Это гипотеза, которую подтвердит или опровергнет живой монитор.
