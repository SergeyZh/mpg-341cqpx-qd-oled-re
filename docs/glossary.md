# Термины

Словарь слов, которые в документах проекта употребляются в особом смысле. Здесь — только
определения и ссылка на место, где термин разобран. Факты остаются в тематических
документах. Новый термин, введённый в ходе исследования, записывается сюда в том же коммите.

Несколько слов в проекте **многозначны** — прежде всего «банк», «FRC» и «ROM». У них перечислены
все значения; в тексте значение нужно указывать явно.

## Регистры скалера и их адресация

**Регистр скалера.** Байтовый регистр кристалла NT68503. С Leon2 он виден как младший байт
32-битного слова, регистры лежат с шагом 4. Доступ — только 32-битными `ld`/`st`
(nt68503-hardware §2.1 (не опубликовано)).

**XDATA-адрес регистра.** Номер регистра в пространстве XDATA ядра 8051, например `0x2678`.
**AHB-адрес** — тот же регистр со стороны Leon2: `AHB = 0xCF000000 + 4 · XDATA`,
для примера `CF0099E0`. Это два имени одного регистра, а не два регистра.

**Банк (регистров).** Один экземпляр набора регистров с общим начальным адресом — **базой**.
Номер банка — позиция его базы в таблице баз, считая с 0.
Регистр банка = база + индекс (§6.1 «Банки регистров» (не опубликовано)).

**Индекс.** Номер регистра от начала банка, один байт. **Без банка индекс регистр не
называет**: `0x78` в разных банках — разные регистры. В тексте пишется «банк вывода 0,
индекс `0x78` (`CF0099E0`)» или просто абсолютный адрес.

**Семейство (банков).** Группа банков, которую прошивка адресует через **одну таблицу баз**:
у всех банков семейства один набор помощников и один смысл индексов. Обычно это несколько
экземпляров одного аппаратного блока (четыре канала вывода — четыре банка вывода).
Но семейство — понятие о **таблицах прошивки**, а не о кристалле, и с блоками оно
совпадает не всегда. Семейства A и M — одни и те же регистры со сдвигом `0xB0`.
В семействе R два «банка» указывают на начало регистрового пространства. Имена
семейств — «банк вывода», M, A, S, L, R, E — перечислены в
§6.1 (не опубликовано).

**Имена семейств и откуда они взялись.** Все имена условные: ни одно не взято из
документации Novatek или строк прошивки MSI. Буквы не образуют ряда «от A до M» — это
отдельные метки разного происхождения, и из самой буквы ничего не следует.

| Имя | Таблица ROM | База банка 0 | Происхождение |
|---|---|---|---|
| банк вывода | `0x15373C` | `2600` | описательное, 2026-09-27: опыты Screen Size показали, что банк 0 задаёт растр и окно на выходе. В старых отчётах — «D-bank», «C-register», `Cbase`, `Q(i,r)` |
| M | `0x15376C` | `1A00` | метка из отчёта indexed-cold (не опубликовано) (2026-09-18, коммит `6f123d2`), столбец «Имя в этом отчёте»; оттуда же `SPACE_M` в `firmware/leon2-main/src/indexed_cold.c`. Смысл буквы не записан |
| A | `0x15374C` | `1AB0` | то же, `SPACE_A`; смысл буквы не записан |
| S | `0x15375C` | `B000` | то же, `SPACE_S`; смысл буквы не записан |
| L | `0x153734` | `4E00` | введено 2026-09-27: таблица используется в пути **л**оготипа |
| R | `0x153728` | `0000`, `0EC0` | введено 2026-09-27: две базы указывают в область регистров п**р**иёмников (receiver); назначение семейства этим не доказано |
| E | `0x153730` | `7B00` | введено 2026-09-27 **без основания**, буква выбрана произвольно; назначение неизвестно |

Однозначно, без условных букв, семейство называется **по адресу таблицы ROM**
(«семейство `15373C`») или **по базе банка 0** («семейство `2600`»). Второе имя сразу
даёт адрес регистра: `CF000000 + 4·(база + индекс)`. Буквы остаются как синонимы для
чтения старых документов и кода.

**Таблица баз.** BE16-таблица в ROM Leon2 Main, откуда помощник берёт базу банка по его номеру.
Их семь, в FW.034 это `0x153728…0x15377B`
(банки в коде Main (не опубликовано)).

**Банк вывода.** Семейство таблицы `0x15373C`, базы `2600 2700 2800 2900 2A00 5D00 2400 2500`.
Банк вывода 0 начинается с `CF009800`. Банки 0…3 соответствуют каналам вывода 1…4.
В старых документах это «D-bank», «C-register», `C54`, `Cbase`, `Q(i,r)`.

**«Банк 8», широковещательная запись.** Номер банка 8 у помощников записи MSI означает
программный цикл по банкам 0…7 (у `8F3D0` — 0…3). Аппаратной широковещательной записи
не найдено.

**Пара младший/старший байт.** 16-битное значение в двух соседних регистрах: младший байт
по меньшему адресу, старший — по адресу `+4`. В банке вывода пара буферизована: младший байт
применяется только записью старшего (проверено записью).

**Помощник (helper).** Функция MSI доступа к регистрам: получает номер банка, индекс и,
если нужно, значение. Номер банка — первый аргумент.

**R8, W8, RMW, R16, W16, R32, W32.** Обозначения операций в листингах и отчётах:
- R8/W8 — чтение или запись младшего байта 32-битного регистра;
- RMW — свежее чтение, изменение по маске, запись;
- R16/W16 — пара младший/старший байт;
- R32/W32 — всё слово.

**`mdw`, `wmem`.** Команды отладочной консоли Leon2 Sub: чтение слов и запись слова по
AHB-адресу. `wmem` — запись в живой регистр, только с согласия владельца
([консоль Sub](console-commands.md)).

## Многозначное слово «банк»

| Где встречается | Что значит |
|---|---|
| регистры скалера | экземпляр набора регистров, см. выше |
| флеш U4002, «bank0/bank1», «банк A/B» | половина 32-МиБ микросхемы, 16 МиБ, со своей копией прошивки — то же, что **слот**. bank0 = банк A = нижние 16 МиБ ([flash-u4002](flash-u4002.md)) |
| GPIO | группа линий GPIO с номером `0x00…0x11` (§6.2 (не опубликовано)) |
| мультиплексор служебной шины ISP | номер в формуле `CF03CD40 + 4×(банк − 1)` (§6.1 (не опубликовано)) |
| профили яркости/контраста в U4003 | первая или вторая таблица профилей (leon2-main-settings (не опубликовано)) |

## Видеотракт

**Растр (активный растр).** Кадр, который скалер выдаёт дальше — панели или в FRC.
В штатном режиме это 3440×1440. Задаётся индексами `0x64/65` и `0x68/69` банка вывода.
Размер растра не меняется при Screen Size 16:9 или 4:3
(osd-menu-functions §8.7 (не опубликовано)).

**Окно картинки.** Прямоугольник внутри растра, куда масштабатор кладёт изображение;
остальное заполняется фоном. Ширина и высота — индексы `0x75/76` и `0x71/72`. Начало —
`0x73/74` (24 + x) и `0x6F/70` (3 + y).

**Масштабатор.** Блок, приводящий кадр источника к размеру окна картинки. Отдельного регистра
коэффициента нет: аппаратура вычисляет его сама из размера кадра и ширины окна
(проверено записью).

**Тайминг, htotal, vtotal.** Полный размер строки и кадра вместе с гашением, в тактах
пикселя и строках. Штатно на выходе 7184 × 1612.

**Канал вывода (output 1…4).** Один из четырёх выходных трактов скалера, у каждого свой банк
вывода. Какие каналы включены, зависит от внутренней раскладки (layout) — даже при одном
окне штатная прошивка включает больше одного канала
(frc-channels (не опубликовано), single-window (не опубликовано)).

**Захват (capture).** Входная часть тракта: измеряет режим источника и принимает кадр
(dp-capture-path (не опубликовано)).

**FRC — два разных устройства.** Значение надо указывать явно:

1. **FRC скалера.** Блок видеотракта внутри NT68503. Когда он включён, в UART Main видно
   `FRC ON`, у тракта до FRC свой тайминг, а окно на выходе задают регистры
   `CF011B00…B1C`. Своя частота — `GPLL_FRC`. В захвате Screen Size при 16:9
   было `FRC OFF`, при 24.5" — `FRC ON`
   (osd-menu-functions §8.7 (не опубликовано)). Что кадровые буферы FRC
   лежат в DDR — предположение ([architecture](architecture.md)).
   Расшифровка аббревиатуры обычная для скалеров — frame rate conversion, — но в
   документации Novatek она не подтверждена.
2. **FRC панели** — контроллер панели (T-CON). В отладочных строках MSI он называется
   `OLED_FRC_*`, строки `OLED set Frame rate control`. Доступ — по I²C, слейв `0x60`,
   16-битные адреса регистров (например, `00B2`). У него своя прошивка и стадии запуска
   `DVDD_ON → FRC_READY → IIC_READY`
   ([oled-panel-abl](oled-panel-abl.md#контроллер-панели-своя-прошивка-есть-из-скалера-она-не-обновляется)).

**T-CON.** Контроллер на стороне панели, то же, что «FRC панели».

**OFF Sensing, EL Sensing.** Команды обслуживания, которые скалер даёт контроллеру
панели (panel-protect-fw034 (не опубликовано)).

Установлено по коду FW.034:
- OFF Sensing — запись `0x0001` в регистр панели `0x0C0`, EL Sensing — такая же запись
  в `0x0C2`. Имена взяты из отладочных строк MSI `OLED set OFF Sensing` и
  `OLED set EL sensing`.
- Всю работу делает панель: скалер не передаёт ей таблиц и не получает результатов.
  Об окончании панель сообщает линией GPIO 10.5, по I²C ответа нет.
- Перед командой панель 180 с стоит без питания, затем включается; её температура
  должна быть не выше 45 °C. На время цикла экран чёрный.
- OFF Sensing выполняется примерно раз в 4 часа работы панели — при выключении, уходе
  в ожидание и вручную. EL Sensing штатная FW.034 не выполняет никогда, хотя код для
  него в образе есть.

Предположение, для этой панели не проверенное. OLED-панели компенсируют старение
пикселей: светящиеся элементы и управляющие ими транзисторы со временем теряют
яркость и смещают характеристики, а панель измеряет это своими цепями и поправляет
сигнал каждого пикселя. OFF Sensing — вероятно, короткий измерительный проход при
выключенном изображении; так обычно корректируют дрейф транзисторов, с чем согласуется
строка `OFFSENSING data Update`. EL Sensing (EL — electroluminescence, само светящееся
вещество) — вероятно, более долгое измерение износа OLED-элементов; у других
производителей такой «длинный» цикл запускают раз в сотни или тысячи часов. Точно
это установит только документация Samsung на панель или прошивка её T-CON; в
репозитории нет ни того, ни другого.

**Panel Protect.** Пункт меню MSI OLED Care и вся процедура обслуживания панели:
расписание, проверки и OFF Sensing.

**OFFS H, ELS Timer H.** Часы включённой панели с последнего OFF Sensing и
с последнего EL Sensing; так их печатает UART Main. Хранятся в U4003 `0x483` и `0x481`.

**Fake sleep.** Состояние штатной прошивки, когда без сигнала монитор выглядит спящим,
но через ~10 минут запускает OFF Sensing.

**Vx1 (V-by-One HS).** Линия от скалера к панели. Передатчик — по контексту блок `CF01Cxxx`
(registers-panel (не опубликовано)).

**Матрица CSC.** Матрица преобразования цвета 3×3 со смещениями, `CF00E984…E9A4`. Через неё
проходят Black Level R/G/B по DDC/CI
(§6.1 (не опубликовано)).

**ACE.** Блок гистограммы кадра, `CF00EE80…EEC8` (§6.11 (не опубликовано)).

**ABL.** Automatic Brightness Limiting — ограничение яркости панели по содержимому кадра.
Отключить его нельзя ([oled-panel-abl](oled-panel-abl.md)).

**Pixel Shift.** Медленный сдвиг изображения самой панелью для защиты от выгорания; скорость
задаётся регистром панели `0x072`. Тёмные полоски по краям экрана — поле этого сдвига,
ход ≈ 15 пикселей по каждой оси
(osd-menu-functions (не опубликовано)).

## Ядра, образы и прошивки

**Main, Leon2 Main.** SPARC-ядро прикладного уровня: меню, EDID, питание, панель.
**Адреса Main** даются от базы 0; смещение в файле = адрес + `0x108000`.

**ROM — многозначное слово.**

| Выражение | Что это |
|---|---|
| «ROM Main», «таблица ROM `0x15373C`», «ROM15373C» | константы образа Leon2 Main. Main не копируется в память: флеш U4002 отображается в его адресное пространство, и ядро читает команды и константы прямо из флеша. Записать туда процессор не может — отсюда «ROM». Адрес ROM Main = смещение в файле прошивки − `0x108000`; например, `0x15373C` → файл `0x25B73C` (§4.1 (не опубликовано)) |
| «масочный ROM» | код, зашитый в сам кристалл NT68503. Исполняется первые ~95 мс после включения, до чтения флеша; в файлах прошивки его нет ([boot-sequence](boot-sequence.md#окно-масочного-rom-95-миллисекунд-и-на-разъёме-в-них-пусто)) |

**RAM Main.** Противоположность ROM Main: блок 112 КиБ по адресам `A8024000…A803FFFF`.
Физически это `0x9F060000…`, **SRAM на кристалле, а не DDR**: DDR — отдельное пространство
кадровых буферов (§2.1 (не опубликовано),
§4.3 (не опубликовано)). Туда при старте
копируются инициализированные данные Main (раздел `id=0x0E`), там же лежат переменные
и стек.
Таблица в RAM — например, автомат меню `A8024248` — может меняться во время работы,
таблица в ROM — нет.

**Sub, Leon2 Sub.** SPARC-ядро приёмной части (HDMI/DP, обучение линка), база `0xA0060000`.
На нём работает консоль с `mdw`/`wmem`.

**Рантайм.** Системная часть программы, которую вызывает прикладной код:
- **рантайм Main** — раздел `id=0x0D` по `0xA0028000`;
- **рантайм Sub** — код Sub по `0xA006xxxx`, который вызывает раздел HDR `id=0x0B`
  ([architecture](architecture.md)).

**STBC.** Ядро 8051, работающее и в standby: владеет флешем и кнопками, запускает остальных.
**STBC Main** (`id=0x01`) — основной образ. **STBC AUX** (`id=0x02`, USB-агент) исполняется на
втором ядре 8051, которое STBC Main выводит из сброса
([architecture](architecture.md#stbc-8051--дежурный-по-системе), nt68503-hardware §2.3 (не опубликовано)).

**Tensilica.** Ядро Xtensa little-endian, раздел `id=0x03`: контур ограничения яркости LDC.

**Портал.** Область общей памяти для команд между ядрами:
- Portal0 `9F0A0100` — STBC;
- Portal1 `9F130100` — Sub;
- Portal2 `B7091000` — Tensilica.

(UART и IPC (не опубликовано)).

**Штатная прошивка (stock), своя (own).** Штатная — прошивка MSI, на мониторе FW.034.
Своя — собственный Main и загрузчики из `firmware/`.

**Адреса FW.034 / FW.037.** По умолчанию адреса в документах — по FW.037
([README](../README.md)). Документы о штатном меню и о своём Main работают с FW.034 и
помечают это. Переносить адрес между версиями сдвигом нельзя.

**Слот.** Половина флеша U4002 со своей копией прошивки; см. «банк» флеша выше.

**Холодный и повторный запуск (cold / warm).** Холодный — после подачи питания или сброса.
Повторный — вход в ту же процедуру без полного сброса, например повторный захват источника
(dp-stable-lifecycle (не опубликовано)).

**Сырой листинг (raw).** Дизассемблированный код без декомпиляции. Доказательством служит
он, а не C из Ghidra: декомпилятор SPARC теряет аргументы из слота задержки
(osd-menu-functions §1 (не опубликовано)).

## Микросхемы, разъёмы и данные экземпляра

**U4002.** SPI-флеш на 32 МиБ, два слота прошивки. Уникальных данных не содержит
([flash-u4002](flash-u4002.md)).

**U4003.** I²C-EEPROM с данными экземпляра: серийный номер, наработка, калибровка,
настройки. Незаменима ([eeprom-u4003](eeprom-u4003.md)).

**`cfg+X`.** Поле блока пользовательских настроек. Блок в RAM Main FW.034 лежит по
`A802BD64`; смещение `X` совпадает со смещением в U4003
(leon2-main-settings (не опубликовано)).

**FE2P.** Flash-emulated EEPROM — механизм хранения данных экземпляра в коде MSI. Фактически
данные лежат в U4003, а окно FE2P во флеше пусто ([fe2p](fe2p.md)).

**U7005.** Микроконтроллер Nuvoton NUC126 на плате. Через него идёт USB-путь к служебной
шине скалера ([mcu-u7005](mcu-u7005.md)).

**ISP.** Режим внутрисхемного программирования скалера: через него читается и пишется
флеш с ПК ([usb-isp](usb-isp.md)).

**CN4008.** Отладочный разъём: четыре UART скалера, по одному на ядро
([hardware-boards](hardware-boards.md)).

## Публикация

**Публичная редакция.** Отдельный публичный репозиторий с собственной историей, куда
экспортируется разрешённая часть этого репозитория. Не копия и не зеркало: состав
задаёт allowlist (publication (не опубликовано)).

**Приватная вставка.** Блок Markdown между `<!-- private -->` и `<!-- /private -->`:
нужен исследованию, но при экспорте вырезается (publication §4.2 (не опубликовано)).

**Публичная правка.** Замена фрагмента текста только в публичной копии файла, записанная
в `publication/edits.toml`; закрытый документ не меняется
(publication §4.5 (не опубликовано)).
