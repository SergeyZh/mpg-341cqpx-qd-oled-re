# Сервисное меню: содержимое и привязка к прошивке

Меню снято с живого монитора (фото `service_menu.jpeg`, FW.034) и сопоставлено с кодом.
Отрисовывает его одна функция — **`0x0002C92C`** в Leon2 Main (адрес FW.037; в FW.034 —
`2C634`, вход, клавиши и действия каждого пункта по FW.034 —
osd-menu-functions §6 (не опубликовано)). Таблица строк меню лежит
по адресам 0x0FBFF8–0x0FC190 (файл 0x203FF8–0x204198 в FW.037), строки — с байтом длины
в начале.

## Что меню подтверждает

Все идентификаторы на экране совпадают с найденными в образе:

| На экране | Где в прошивке |
|---|---|
| `FW.034 20251031` | строка версии, ровно та, что дал строковый дифф |
| `SDC QMC340CA01_D01` | блок `55AA6699 PANEL` |
| `MPG341CX OLED` | имя дисплея во всех 60 блоках EDID |
| `NT68503` | см. ниже |

**Кажущееся противоречие с диффом версий разрешилось.** Дифф показал, что конфиг-блок
`55AA6699 SCALER` есть только в FW.037, а монитор на FW.034 при этом выводит `NT68503`.
Объяснение: в FW.034 есть *простая строка* `NT68503` (файл 0x203DF9), которую и печатает
меню; новым в 037 является именно конфиг-блок, а не сам факт наличия имени. Вывод в
`docs/version-diff.md` остаётся верным.

## Полный список пунктов

Из таблицы строк, включая значения, не попавшие на фото:

```
Picture Check | Burnin Room | User Burnin | OFF     <- состояния пункта "Burn In"
HDMI CTS   NO / OK   B  G  R
Freq   Ratio   SSC
Sensing Test      CRC AUTO      CEC PWM Adjust
Init   Panel   PCB   DP CTS   SN:   Reset
Monitor On Time   EDID WP   Burn In   PRODUCT
CON  BRI  Normal65  User  Cool93  Warm50
```

То есть у **Burn In** четыре состояния, а не два: `OFF`, `Picture Check`, `Burnin Room`,
`User Burnin`. Это заводские режимы прогона, и они логично стыкуются с командами панели
**Inspection Mode (0x1C6)** и **Inspection Pattern (0x1C8)** из `docs/oled-panel-abl.md`.

**Sensing Test** — тот же тракт, что команды **OFF Sensing (0x0C0)** и
**EL Sensing (0x0C2)**: принудительный запуск циклов компенсации панели.
**Поправка 2026-09-27:** по коду FW.034 пункт цикл не запускает. Он ставит флаг
`SysParam 0x10` (бит 7 U4003 `0x489`), и тогда порог OFF Sensing считается в минутах
(≥ 20 мин вместо ≥ 4 ч), а системный блок пишется раз в 10 мин
(panel-protect-fw034 §4.1 (не опубликовано)).

## Переменные в DRAM

Восстановлены из декомпиляции `0x0002C92C`. При поднятой UART-консоли читаются
командой `mdw` без всякой модификации прошивки.

| Адрес | Что |
|---|---|
| 0xA802CC88 | **Monitor On Time** — счётчик наработки (на фото 843 / 17) |
| 0xA802BD5E | длина серийного номера |
| 0xA802BD5F | серийный номер (`DD0T134700168`) |
| 0xA802BD7D / 0xA802BD7E | BRI / CON |
| 0xA802CCD6..D8 | Warm50 R/G/B |
| 0xA802CCD9..DB | Normal65 R/G/B |
| 0xA802CCE2..E4 | Cool93 R/G/B |
| 0xA802BD86..88 | User R/G/B (хранится в процентах, пересчёт `x*0xFF+0x32` /100) |

Адреса Warm50/Normal65/Cool93 — FW.037, где RAM-кэш заводского блока `U4003:0x0440`
начинается с `0xA802CCD0` (`+06`, `+09`, `+12`). В FW.034 тот же кэш лежит на
`0xA802CCC0`, то есть на 16 байт ниже: [eeprom-u4003.md](eeprom-u4003.md#блок-0x0440-заводской-цветовой-блок-2026-09-25).

Ревизии железа берутся вызовами: `FUN_000778CC()` → PCB (34), `FUN_000774E4()` → Panel (27).

## Два практически важных пункта

### CRC AUTO = ON

> **Опровергнуто 2026-09-27 кодом FW.034:** пункт управляет режимом приёмника
> видеовхода (команда Sub `0x86`), а не проверкой образа, и в EEPROM не сохраняется —
> osd-menu-functions §6.3 (не опубликовано).
> Там же полный разбор пунктов меню по FW.034 (§6). Текст ниже — исходная гипотеза.

Самая ценная строка на экране. Прошивка имеет автоматическую проверку контрольной суммы,
и это **переключаемый пункт меню**, а не константа. Если его удаётся выставить в OFF,
исчезает главный барьер для самосборной прошивки — тот самый, который я не смог закрыть
разбором загрузчика (формат контрольной суммы уходит в банковый вызов, см.
`docs/bootloader.md`).

Это стоит проверить в первую очередь: переключение пункта меню несравнимо дешевле,
чем реверс алгоритма CRC.

### EDID WP

> **Уточнение 2026-09-27 по коду FW.034:** пункт пустой — ни нажатие, ни правка
> значения ничего не пишут (только курсор тайлов OSD),
> osd-menu-functions §6.2 (не опубликовано). Текст ниже —
> исходное предположение.

Пункт защиты EDID от записи. Значит EDID **пишется в системе** и меню умеет снимать
защиту. К цели по кадровой частоте это, впрочем, ничего не добавляет: выше 240 Гц
в таблицах нет ничего, и предел задаёт панель (`docs/external-research.md`).
Полезно скорее для экспериментов с таймингами и для восстановления EDID после ошибок.

## Чего в меню нет

Ни одного параметра ABL: ни `LimitUpperBound`, ни `ADIM`, ни `ZonePeakingPercent`,
ни доступа к регистрам панели. Нет и настроек кадровой частоты.

То есть надежда, что сервисное меню откроет управление яркостью, **не оправдалась**.
Оно даёт заводскую диагностику, счётчики, режимы прогона и калибровку белой точки —
но контур ограничения яркости остаётся задачей для UART-консоли и прошивки.

## Данные, которые нельзя затирать при перепрошивке

Меню наглядно показывает, что в мониторе есть уникальные для экземпляра значения:
наработка 843 часа, серийный номер `DD0T134700168`, ревизии PCB и панели, калибровка
белой точки. В файлах MSI их нет и взяться им неоткуда.

Хранятся они в области FE2P (эмуляция EEPROM во флеше; в прошивке — `FE2P WriteByte`,
`FE2P_SetLeon2BaseAddress`, `CMD_FE2P_SETEXTEND`). Точное расположение FE2P в образе
пока не установлено — это нужно закрыть до первой записи во флеш.
