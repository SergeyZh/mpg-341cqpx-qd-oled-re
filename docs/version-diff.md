# Сравнение FW.034 и FW.037

Оба образа лежат в репозитории. Воспроизвести:

```
.venv/bin/python tools/fwdiff.py \
    MSI_MPG_341CQPX_QD-OLED_FW.034_D728.bin \
    MSI_MPG_341CQPX_QD-OLED_FW.037_0225.bin --strings
```

|  | FW.034 | FW.037 |
|---|---|---|
| Размер | 2 530 816 (0x269E00) | 2 531 840 (0x26A200) |
| Сборка | Oct 14 2025 11:14:55 | Nov 10 2025 09:47:58 |
| Метка версии | `FW.034 20251031` | `FW.037 20260324` |
| Блок `SCALER` | отсутствует | `NT68503` |
| Блок `PANEL` | `SDC QMC340CA01_D01` | то же |

## Почему побайтовый дифф здесь бесполезен

Образы отличаются на 1024 байта, поэтому весь код после первой вставки сдвинут.
Побайтовое сравнение показывает 58 % расхождений — это артефакт выравнивания,
а не объём реальных изменений. Читать нужно строковый дифф.

## Что действительно изменилось

Из ~5 280 строк общими остались 5 221. Реальная разница мала:

- **Появились конфиг-блоки `55AA6699 SCALER` и `VERSION`.** В 034 их нет вовсе —
  то есть в 037 добавлена сама схема описания версий/платформы.
- **Новая трассировка в тракте тональной компрессии HDR:**
  `[1]/[2]DRV_PQ_VEP_SetXvYccTMOLL_LoadTable_EOTFBoost = %d`. Это путь PQ/VEP,
  загрузка таблицы xvYCC tone mapping и «буст» EOTF — напрямую про яркость.
  Существенно, что добавлена именно **отладочная печать**: похоже, MSI правила
  или отлаживала эту область между версиями.
- **Новое сообщение `isp on start...`** — в тракте обновления прошивки. **Разобрано
  2026-08-28, и это самое содержательное функциональное различие версий, какое пока
  найдено:** в FW.037 добавлен **вход в ISP по команде DDC/CI** — `Set VCP Feature`
  (`0x03`) с кодом VCP `0xFB`, без проверки значения и без гейта заводского режима.
  Печать `isp on start...` идёт из `ServicePort_EnableIsp` (`A002FD00`), нового экспорта
  служебного рантайма. Таблицы переходов обработчика DDC/CI сравнены целиком: в FW.037
  обработчиков **35**, в FW.034 — **34**, и единственное различие — `0xFB`; остальные
  34 опкода совпадают. Разбор условия — `docs/ddcci.md`, каналы служебной шины —
  `docs/scaler-service-runtime.md`. Практическое следствие: отрицательный результат
  «сервисной плоскости на видеоразъёме нет» снят на FW.034 и к FW.037 не относится
  (`docs/ddc-external-probe.md`).
- Прочая разница (около 50 строк с каждой стороны) — двоичный мусор, случайно
  попавший в печатаемый диапазон, и сдвинутые фрагменты одних и тех же
  локализованных строк OSD.

## Официальный changelog MSI

> Fixed Display Flicker under HDR content in EOTF Boost mode.

Это ровно то, что показал строковый дифф до того, как changelog стал известен: единственная
содержательная новая строка — `DRV_PQ_VEP_SetXvYccTMOLL_LoadTable_EOTFBoost`. В FW.034 строк
`DRV_PQ_VEP` нет вообще, то есть трассировка в этом тракте добавлена целиком.

Строки лежат на 0xC6968 и 0xC69A0, то есть в разделе **id=0x0B**, база которого установлена
как **0x9F1B0000** (85 % целей `sethi`+`jmp` попадают на начала функций против 8 % у следующего
кандидата). Раздел подключён к Ghidra как `part0b` — 287 функций, 24 018 инструкций.

## Что сравнение регионов даёт наверняка

Регионы, лежащие в обоих образах на одинаковых смещениях, сравнимы побайтово:

| Регион | Результат |
|---|---|
| Загрузчик 8051 | **идентичен** |
| Таблица JEDEC | **идентична** |
| Раздел 8051 id=0x01 | **идентичен** |
| Раздел 8051 id=0x02 | **идентичен** |
| **Таблицы EDID** | **идентичны** |
| Таблица разделов | 9 байт (обновлены размеры) |
| Раздел id=0x03 (Tensilica Xtensa) | пересобран |
| Leon2 Sub | пересобран |
| Раздел 0x0B | пересобран |
| Раздел 0x0D, service runtime Main | пересобран: `0x7B3C` → `0x80C8` |
| Leon2 Main | пересобран |

Два вывода отсюда твёрдые:

- **EDID не менялись вообще** — значит между версиями не трогали ни один режим и ни один
  предел по кадровой частоте. Для цели «увеличить частоту» это ещё одно отрицательное
  свидетельство: 240 Гц не является недавно поднятым потолком.
- **Весь тракт standby-контроллера (8051 id=0x01/0x02 и загрузчик) не изменился** —
  кнопки, питание и логика загрузки те же.

Остальные разделы пересобраны: подбор общего сдвига даёт лишь 63–86 % совпадений, то есть
изменилась разметка функций. Побайтовым диффом конкретную правку из-за этого не выделить —
нужна пофункциональная сверка в Ghidra.

Для `id=0x0D` такая сверка выполнена отдельно (`docs/scaler-service-runtime.md`).
Архитектура не изменилась: это всё тот же runtime Leon2 Main с trap/IRQ/GPIO-I2C,
таймерами, MMIO и mailbox. Но абсолютные адреса после `0xA002A878` сдвинулись.
Критичный пример: `Mailbox_SendCommand` находится по `0xA002F3EC` в FW.034 и по
`0xA002F770` в FW.037. В 037 также появился новый экспорт входа в service ISP,
связанный с новой строкой `isp on start...`.

## Вывод для целей проекта

Между 034 и 037 **нет признаков изменения алгоритмов защиты панели** —
ни новых команд OLED T-CON, ни изменений в наборе `ADIM/PDIM/ZonePeaking`.
Единственная содержательная зацепка по яркости — добавленная трассировка
`EOTFBoost` в PQ/VEP. Это делает `DRV_PQ_VEP_SetXvYccTMOLL_LoadTable_EOTFBoost`
хорошей точкой входа при разборе тракта HDR-яркости (фаза 4).

Ожидание, что дифф версий сразу покажет тюнинг ABL, **не подтвердилось**:
обновление выглядит как обычный пересбор с точечной правкой в тракте HDR.

`DRV_PQ_VEP_SetXvYccTMOLL_LoadTable_EOTFBoost` — хорошая точка входа при разборе
тракта HDR-яркости (фаза 4), но искать её придётся в Ghidra по коду: строки в разделе
0x0B адресуются через базовый регистр, а не парами `sethi`/`or`, поэтому автоматический
поиск ссылок на них ничего не даёт.
