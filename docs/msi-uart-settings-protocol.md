# MSI UART settings protocol (`58`/`5b`)

Служебный протокол настроек связывает приложение на ПК с Leon2 Main через USB-мост
`U7005`:

```text
ПК → USB HID Report ID 1 → U7005 UART1 → STBC channel4 → Mailbox → Leon2 Main
```

Его формат сначала был восстановлен по прошивкам `U7005` и Leon2 Main, а затем
подтверждён живым USB-захватом. Открытый проект
[`couriersud/msigd`](https://github.com/couriersud/msigd) даёт третье, независимое
подтверждение транспорта и, что важнее, словарь назначений команд для многих моделей
MSI. Этот документ фиксирует результат сопоставления с MPG 341CQPX QD-OLED FW.034.

Нумерация уточнена 2026-09-17: приёмник этого канала в Main FW.037 —
`6D8E4→59B08(4)`. Строка `Uart3` в старом описании относилась к соседнему
парсеру channel3. Сопоставление каналов (не опубликовано).

## Независимое подтверждение формата

`msigd` использует HID-отчёты длиной 64 байта. Первый байт — Report ID `0x01`, за ним
идёт ASCII-команда, завершённая `CR`; остаток отчёта заполняется нулями. Реализация:

- [`src/phid.h`](https://github.com/couriersud/msigd/blob/master/src/phid.h) —
  `PACKETSIZE = 64`, `hid_write()` и `hid_read_timeout()`;
- [`src/msigd.cpp`](https://github.com/couriersud/msigd/blob/master/src/msigd.cpp) —
  `write_command()`, `get_setting()` и `set_setting()`.

Формат полностью совпадает с прошивкой и захватом:

```text
HID OUT:  01 | ASCII command | 0D | 00 ...
HID IN:   01 | ASCII reply   | 0D | 00 ...

GET:      5 8 ID[4] index \r
response: 5 b ID[4] index data... \r

SET:      5 b ID[4] index data[3] \r
ACK:      5 6 0 0 (+|-) \r
```

В терминах `msigd` чтение строится как `"58" + setting.m_cmd`, запись — как
`"5b" + setting.m_cmd + encoded_value`, а успешный ответ на запись сравнивается с
`5600+`. Таким образом, это тот же UART-протокол Leon2, а не DDC/CI.

`msigd` не содержит перехода `580040:\r`, Report ID `0x04`, ISP-опкодов `0x78`,
`0x87`, `0x25` или чтения памяти скалера. Он остаётся на верхнем уровне настроек OSD и
не переключает UART в I2C Slave/ISP. Низкоуровневый протокол описан отдельно в
`docs/nt68503-i2c-service-protocol.md`.

## Кодирование чисел

Функции `msi_utos()`/`msi_stou()` в `msigd` независимо подтверждают, что разряд
кодируется одним байтом `0x30 + n`, а не десятичной или шестнадцатеричной цифрой:

```text
0..9  → '0'..'9'
10    → ':'
11    → ';'
12    → '<'
13    → '='
14    → '>'
15    → '?'
16    → '@'
17    → 'A'
```

Поэтому `:` в `580040:\r` — индекс 10, а не разделитель. То же кодирование применяется
к трёхбайтным значениям. Например, ответ `bbb` команды `00434` означает RGB
`50,50,50`, потому что `0x62 - 0x30 = 50`. Для отдельных полей `msigd` использует
другие основания: тройка RGB упаковывается тремя байтами с основанием 1000, время
будильника — с основанием 60.

## Сопоставление с MPG 341CQPX FW.034

В `captures/usb-isp/usb-03-tool-probe.txt` есть 69 запросов верхнего уровня: 68 кадров
`58...` и один `6800;30`. Из 68 кадров:

- 41 точно совпадает с ID настроек `msigd`;
- `00140` и `00150` объясняются отдельным кодом идентификации `msigd`;
- `001<0` уже независимо установлен как версия прошивки Leon2 Main.

Итого назначение известно у **44 из 68** запросов с префиксом `58`. До изучения
`msigd` были названы только серийный номер, версия прошивки, яркость и контраст; внешний
словарь добавил около 40 новых назначений.

### Идентификационная тройка

`msigd` определяет модель по паре `00140`/`00150`, а не по версии прошивки скалера:

```text
MPG 341CQPX FW.034:
00140 → 30 30 A5       # условная запись: 00<0xA5>
00150 → "V22"
001<0 → "034"         # версия прошивки Leon2 Main, не используется msigd
```

Следовательно:

- `00140` — специальный идентификатор модели/семейства;
- `00150` — версия поколения команд OSD/UART либо второй компонент идентичности;
- `001<0` — собственно FW.034.

Пары `00 A5`/`V22` нет ни в `master`, ни в открытых PR `msigd` на 2026-08-17. Однако
PR для близких OLED-моделей подтверждают, что та же схема продолжает использоваться:

| Источник | Модель | `00140` | `00150` | Примечание |
|---|---|---|---|---|
| [PR #58](https://github.com/couriersud/msigd/pull/58) | MEG 342C QD-OLED | `00 90` | `V58` | FW.026 |
| [PR #64](https://github.com/couriersud/msigd/pull/64) | MPG 271QX/271QRX QD-OLED | `00 9E` | `V20`/`V22` | `V22` для FW.012 |
| [PR #70](https://github.com/couriersud/msigd/pull/70) | MPG 274URDFW E16M QD-OLED | `00 B4` | `V21` | сопоставлен существующей серии |
| [PR #71](https://github.com/couriersud/msigd/pull/71) | MD342CQP | `00 A0` | `V20` | тот же USB HID `1462:3FA4` |

Совпадение `V22` с MPG 271QX показывает близкое поколение протокола, но **не означает
одинаковую модель или одинаковый enum всех настроек**: первый компонент идентичности у
MPG 341CQPX другой.

### Что именно объяснилось в живом захвате

Помимо уже известных `00130`, `001<0`, `00400`, `00410`, получили имена:

```text
00110 macro_key             00120 mode                  00140 model identity
00150 protocol identity     00170 frequency             00200 game_mode
00230 enable_dynamic        00240 hdcr                  00250 refresh_display
00251 refresh_position      00260 alarm_clock           00263 alarm_position
00270 crosshair/icon        00271 crosshair_color       00280 adaptive_sync
002:0 screen_size           002;0 night_vision          00300 pro_mode
00310 eye_saver             00340 image_enhancement     00420 sharpness
00430 color_preset          00434 color_rgb             004:0 gamma
00500 input                 00510 auto_scan             00600 pip/pbp
00620 secondary_input       00630 pip_size              00640 pip_position
00810 osd_transparency      00820 osd_timeout           00830 screen_info
00880 power_button          008:0 hdmi_cec              008>0 kvm
00900 navi_up               00910 navi_down             00920 navi_left
00930 navi_right
```

Ответ `00500 → 002` согласуется с DisplayPort: у большинства описанных `msigd`
моделей enum входов равен `0=HDMI1`, `1=HDMI2`, `2=DP`, `3=USB-C`. Для MPG 341CQPX
это пока сильное сопоставление, но не независимая проверка меню.

`00110` в `msigd` прямо назван `macro_key`, помечен read-only и описан как часто
опрашиваемый OSD-приложением. Поэтому ежесекундный `5800110\r` от резидентного
компонента MSI — опрос Macro/Navi key, что хорошо согласуется с именем процесса
`MonitorMicroKeyDetector.exe`. Второй кадр heartbeat, `6800;30`, в `msigd` отсутствует
и остаётся неизвестным.

Единственная запись в конце опроса, `<d0>b00100000\r`, имеет ID/index `00100`, который
`msigd` называет `power`. Это полезное совпадение, но не готовая расшифровка: префикс
`0xD0` отличается от обычного `'5'`, команда не выключает монитор, а в `msigd` поле
`power` разрешено только для одной старой серии. Возможно, `U7005` или Leon2 трактует
этот префикс отдельно.

## Безопасность записей

Словарь нельзя превращать в автоматический перебор SET. Сам автор `msigd` предупреждает,
что прошивка мониторов не защищена от неподдерживаемых обращений и ошибочная запись может
сделать монитор неработоспособным. В исходнике дополнительно зафиксировано:

- `00840 reset` полностью отключена как опасная;
- `00800 osd_language` сделана read-only: неверное значение может повредить настройки;
- неизвестная трактовка `00280` на старой модели после записи требовала выключения и
  включения питания;
- отдельные Screen Size-команды убивали USB-интерфейс до переподключения питания.

Поэтому назначения ID из `msigd` надёжны как подсказка для **чтения**, но запись
допустима только после проверки конкретного enum на MPG 341CQPX. Главный источник
предупреждения — [`README.md` проекта](https://github.com/couriersud/msigd/blob/master/README.md).

## Источники и степень уверенности

1. **Высокая:** байтовый формат — одинаков в прошивке Leon2 Main, прошивке `U7005`,
   живом USB-захвате и реализации `msigd`.
2. **Высокая:** имена ID — прямые константы исходного кода `msigd`; 41 ID точно
   совпадает с нашим захватом.
3. **Средняя:** значения enum — часто различаются между моделями, поэтому старые
   таблицы нельзя без проверки переносить на MPG 341CQPX.
4. **Гипотеза:** оставшиеся новые ID относятся к OLED Care/Panel Protect; открытый код
   их не расшифровывает.

Основные внешние источники:

- [`couriersud/msigd`](https://github.com/couriersud/msigd);
- [`src/msigd.cpp`](https://github.com/couriersud/msigd/blob/master/src/msigd.cpp);
- [`src/phid.h`](https://github.com/couriersud/msigd/blob/master/src/phid.h);
- [открытые pull requests](https://github.com/couriersud/msigd/pulls), включая OLED-модели.


## Проверка со своей STBC (2026-09-18)

Аппаратный опрос после запуска кандидата банка 1 (не опубликовано)
дал 2412/2412 корректных ответов на 12 выбранных GET, включая Main version `034`,
protocol identity `V22` и настройки изображения. Медиана 11,795 мс, p95=14,693 мс,
максимум 17,481 мс; последовательный опрос без добавочной паузы — 74,06 запроса/с.
Банк атрибутирован по предшествующему сообщению владельца, а не по версии Main.
Сохранены полные HID OUT/IN; SET, ISP и standby этим опытом не проверены.

Для проверки сквозного канала нельзя использовать один `5800110`: в
`firmware/u7005/src/bridge.c` он обрабатывается локально, возвращает Macro/Navi
status и очищает защёлку события, не вызывая `uart_write`. Аналогично `5800130`
может получать локальный серийный номер из настроек U7005. Выбранные 12 GET
попадают в UART-ветвь и проверяют прохождение через STBC Mailbox к Main и обратно.
